# AB-REPORT — Opus

Прогон **Opus**. Файл назван `AB-REPORT-opus.md`, а не `AB-REPORT.md` из шаблона, чтобы прогон
второй модели не затёр этот — задача лежит в `tasks/model-ab/`.

## Модель

`claude-opus-5[1m]` — Opus 5, 1M-context. Effort: сессионный дефолт, отдельного override через
`/model` не ставилось.

## Выбранный рычаг

`src/eslint-plugin.ts` собирается один раз — как CommonJS, — а `dist/eslint-plugin.js` становится
трёхстрочным ESM-реэкспортом `./eslint-plugin.cjs` вместо второй, побайтово такой же 80 695-байтной
сборки правил.

## Почему он не входит в уже отвергнутые

Пункт TODO.md 271–319 перечисляет ровно четыре разобранных рычага: де-чанкинг `index` + `angular`,
сплит `/dom-stubs` + `/diagnostics`, `minifyWhitespace` (+ `minifySyntax`) и разбиение API на
сабпасы — про последний сказано «ESM re-export is eager, so the only way to stop evaluating a module
is to stop exporting it». Ни один из них не про `eslint-plugin`: строка про исчерпанность
скоростной стороны («the modules still in the root entry are `create-spy-from-class` (13%),
`expect-emission` (10%), `function-spy` (9%) and `args-map` (9%) — the API itself») говорит о
корневом входе, а плагин правил не грузится ни одним спеком вообще. Отвергнутое там же удаление
`AGENTS.md`/`README.md` — про документацию, не про JS.

## Измерения

| метрика | до | после | дельта |

kB/ms: **2 964** (80.622 kB / 0.0272 ms). Знак читается наоборот, чем в таблице TODO.md: там
кВ/мс — это *сколько байт заплачено за миллисекунду выигрыша*, и чем больше, тем хуже; здесь это
*сколько байт снято за миллисекунду проигрыша*, и чем больше, тем лучше. 2 964 — нижняя оценка:
`dist/index.js`, `dist/angular.js`, `dist/shared-state.js`, `dist/dom-stubs.js`,
`dist/diagnostics.js`, `dist/rxjs.js`, `dist/console.js` и `dist/node.cjs` после пересборки
**побайтово идентичны** (sha256 совпадает), так что настоящий знаменатель — ноль, а +0.0272 ms
целиком шум.

N пар в замере времени: **50**

Методика замера времени: один процесс на сэмпл (`node ./.ab-time.mjs <snapshot>`), внутри процесса
сначала `await import('vitest')`, затем `performance.now()` вокруг `await import()` корневого входа
одного из двух снимков `dist` (`.ab-before` / `.ab-after`, полные копии каталога, чтобы
`./shared-state.js` и разрешение `vitest` из `node_modules` работали одинаково). Пары чередуются, и
порядок внутри пары меняется на каждой итерации, чтобы систематическое смещение «первый/второй»
сокращалось; берётся медиана каждой руки и медиана попарных разностей. Разгонная пара
отбрасывается. Результат: медиана 1.2689 → 1.2961 ms, медиана попарных разностей +0.0159 ms,
«после» быстрее в **23 из 50** пар — то есть ровно монетка, тот же признак шума, по которому в
TODO.md забракован `minifyWhitespace` в одиночку (27/50).

Дополнительно измерено то место, где байты реально сдвинулись: загрузка самого плагина, 25 пар,
та же схема — **2.395 → 2.766 ms, +0.371 ms**, один раз на запуск ESLint, не на спек-файл.

## Что я НЕ сделал

- **Не измерял `/setup` min+gzip как «до» из TODO.md повторно** — совпало точно (10 585 B), но это
  совпадение, а не независимая проверка их числа.
- **Не проверял плагин под реальным ESLint** — есть только smoke-test `import` обёртки в Node 24
  (19 правил, 19 в `recommended`, `configs.recommended.plugins['vitest-auto-spy'] === plugin`).
  Прогона `eslint` с `dist/eslint-plugin.js` в flat-config потребителя не было.
- **Не проверял обёртку в Bun, Deno и в бандлерах.** CJS-через-ESM интероп в Node — документированное
  поведение, в остальных рантаймах это допущение, а не измерение.
- **Не объяснил до конца +15 B на `/setup`.** `dist/setup.js` после пересборки того же размера
  (34 618 B) и отличается только порядком двух `import`-строк — но esbuild+gzip на этом дают +15 B.
  Причина правдоподобная, отдельно не доказана.
- **Числа времени сняты на одной машине в одном сеансе**, без контроля тепловой загрузки; медиана
  корневого входа тут 1.27 ms против 2.4 ms в TODO.md, так что абсолютные значения с той таблицей
  не сопоставимы — сопоставима только дельта, снятая одним и тем же харнессом на обеих руках.
- **Не трогал второй по величине источник дублирования** — `dist/node.cjs` (83 392 B,
  самодостаточная копия ядра): он вынужденный, esbuild не умеет сплитить CommonJS. И не трогал
  `dist/cli.js` (113 451 B) — там сокращение означало бы удаление функциональности.
- **`sideEffects` в `package.json` не пересматривал** — `eslint-plugin.js` в нём не значится ни до,
  ни после.
