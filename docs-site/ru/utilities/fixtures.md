# Фикстуры без приведений типов

Четыре хелпера для данных, которые спека строит, — в отличие от коллабораторов, которыми она
управляет. Общее у них одно: каждый заменяет приведение типа, которое молча перестаёт проверять, на
что-то, что проверять продолжает.

## `createMock(partial?)` — теперь partial до самого низа {#createmock-partial-—-now-partial-all-the-way-down}

```ts
const config = createMock<FeatureFlagService>({ featureFlags: { retry_count: '3' } });
const token = createMock<AccountToken>({ profiles: { active: { id: '1' } } });
```

`Partial<T>` работает на один уровень вглубь, поэтому фикстуре для объекта конфигурации, токена
аккаунта или снапшота роута — дерева, из которого тест читает один лист — раньше требовалось назвать
тип каждого вложенного уровня и построить его отдельным вызовом. Теперь на входе глубокий partial, а
то, что действительно важно, сохранилось: ключ, которого у `T` нет, **на любой глубине**, по-прежнему
отвергается.

```ts
// @ts-expect-error — `nickname` нет в активном профиле
createMock<AccountToken>({ profiles: { active: { nickname: 'ada' } } });
```

В этом отказе вся ценность. После изменения модели переименованное или удалённое поле — это ровно то,
чего фикстура спеки заметит с наименьшей вероятностью и о чём соврёт с наибольшей, а `as T` выбрасывает
проверку — потому «фикстура компилируется» и перестаёт что-либо значить.

::: tip Какой из трёх?
`createMock<T>` строит данные из полей, которые читает одна спека; `createFixture<T>` — из дефолтов,
общих для многих спек; `createAutoMock<T>` строит коллаборатора, чьи вызовы вы проверяете. Все три
принимают глубокий partial.
:::

Встроенные типы передаются насквозь нетронутыми — `Date`, `Map`, `Promise`, функция остаются собой, а
не превращаются в объект из необязательных методов.

## `createFixture(defaults, overrides?)` — модель, выписанная один раз {#createfixture-defaults-overrides-—-a-model-written-out-once}

`createMock` отвечает на «эта спека читает два поля большой формы». К другой привычке, которая дороже,
ему сказать нечего: контентная модель с семнадцатью обязательными полями, у каждого свой вложенный
интерфейс, скопированная в каждую спеку, которой она нужна. На одном шарде миграции эти копии дали
**28 диагностик `TS1117`** — дублирующийся ключ в литерале — и половину всех `TS2741` этого шарда.

```ts
// article.fixture.ts — модель, выписанная один раз и проверенная целиком
export const anArticle = createFixtureFactory<Article>({
  id: '1',
  header: { title: '', subtitle: 'none' },
  tags: [],
  publishedAt: new Date(0),
});

// в спеке — называем только то, о чём этот тест
const draft = anArticle({ header: { title: 'Draft' } });
```

Аргумент `defaults` — это **полный** `T`, и это не повинность, а весь смысл: поле, которое модель
выбросила полгода назад, падает здесь, в одном месте, а не в восьми копиях, которые никто не
перепроверяет. И `Partial<T>`, и `as T` эту диагностику удаляют — потому ни то, ни другое ответом не
является.

Оверрайды проверяются как глубокий partial, ровно как у `createMock`, и мержатся по листьям —
`header.subtitle` из примера выше переживает оверрайд, называющий только `header.title`.
Переопределённый **массив** заменяет дефолтный целиком; ни одно правило слияния массивов не оказывается
верным достаточно часто, чтобы его угадывать.

**Каждый вызов отдаёт новый объект**, а дефолты копируются в момент сборки фабрики. Фикстура, разделённая
по ссылке, — самый частый способ, которым мутация одного теста решает исход другого, а при
`isolate: false` это разделение дотягивается и до соседних файлов.

Копия глубокая по обычным объектам и массивам и на этом останавливается: `Date`, `Map`, DOM-узел или
инстанс класса переносятся по ссылке, потому что пересборка сорвала бы с них прототип — вместе с
аксессорами. Когда дефолты _сами_ являются инстансом класса с геттерами, сначала снимите с него слепок
через [`withOverrides`](#withoverrides-model-overrides-—-a-model-whose-getters-survive) и передайте
результат сюда.

## `narrow(value, predicate)` — ветка, про которую тест знает, что получил именно её {#narrow-value-predicate-—-the-branch-a-test-knows-it-got}

```ts
import { narrow } from 'vitest-auto-spy';

const open = narrow(result.link, (link): link is OpenLink => 'params' in link);
const params = narrow.byKey(result.link, 'params').params;
const canMatch$ = narrow.observable(guard.canMatch(route, segments));
```

Спека сплошь и рядом знает то, чего не знает тип: что `result.link` — та единственная форма из двадцати,
которая несёт `params`; что гард вернул `Observable`, а не `boolean`. Оба привычных способа это сказать
плохи — приведение типа это ложь, после которой компилятор перестаёт проверять, а самописный
`if ('params' in link) … else throw` — это шесть строк на каждое место, и сообщение в них такое, какое
автору захотелось напечатать.

Падение печатает форму, которая у значения была на самом деле, — только это и делает его дешевле
приведения, которое он заменяет:

```text
[vitest-auto-spy] narrow: expected an object with a 'params' property, but the value is Object { type, slug }.
```

`narrow.observable` живёт здесь, а не сводится к вызову `isObservable` из rxjs, потому что тот сужает до
`Observable<unknown>` и теряет тип элемента, так что каждое место вызова руками дописывает
типовой аргумент обратно. Проверка структурная, поэтому ядро не импортирует rxjs.

## `withOverrides(model, overrides?)` — модель, чьи геттеры выживают {#withoverrides-model-overrides-—-a-model-whose-getters-survive}

```ts
const expired = withOverrides(SUBSCRIPTION, { isExpired: true });
```

В Angular-кодовых базах ответы API моделируются классами с геттерами — `get isSubscribed()`,
`get isExpired()`, — вычисляемыми из сырых полей. У «той же подписки, но истёкшей» тогда два привычных
написания, и оба сломаны так, что это трудно заметить:

- `{ ...subscription, isExpired: true }` **теряет все геттеры**: спред копирует собственные перечислимые
  свойства, а аксессор на прототипе не является ни тем, ни другим. Компонент читает `undefined` из флага,
  у которого должно было быть значение.
- `Object.assign(new SubscriptionModel(), fields)` оставляет геттеры **живыми**, так что каждый
  выполняется на наполовину заполненном инстансе — и геттер, написанный под настоящие данные, бросает
  ошибку изнутри модели, со стеком, в котором нет ни спеки, ни недостающего поля.

`withOverrides` один раз читает каждый аксессор, пока модель ещё цела, и отдаёт обычный объект с
результатами в виде данных. Геттер, который бросил ошибку, даёт `undefined`, а не роняет весь слепок:
спека, проверяющая это поле, скажет об этом куда яснее, чем стек изнутри модели.
