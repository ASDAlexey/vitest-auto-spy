# `fakeAsync` на Vitest

```ts
// vitest.setup.ts
import 'vitest-auto-spy/zone';
import 'zone.js';
import 'zone.js/testing';
```

`zone.js/testing` патчит три раннера: jasmine, mocha и jest. Vitest среди них нет, поэтому в
Angular-проекте на Vitest **каждый** `fakeAsync` падает:

```text
Error: Expected to be running in 'ProxyZone', but it was not found.
```

Сообщение про зону — в тесте, который ни о какой зоне не упоминает.

zone.js 0.16.2 (2026-05-06) действительно поставляет свой патч — `zone.js/plugins/vitest-patch`, — но он
opt-in, и никто не подключает его за вас: `zone.js/testing` его не включает (в его бандле лежат патчи
для jasmine, mocha и jest, а строка `vitest` не встречается ни разу), и `@angular/build:unit-test` тоже
— во всех версиях с 20 по 22 он лишь дописывает `zone.js/testing` в полифилы. Единственный пакет,
подключающий патч побочным эффектом, — `@analogjs/vitest-angular`, через `…/setup-zone`; так что проект,
переезжающий на нативный билдер, теряет и это вместе с Analog.

Импортировать официальный плагин руками — тоже не ответ, а людям сейчас активно советуют именно это.
ng-mocks предписывает ровно такой порядок загрузки в своём руководстве по установке — `zone.js`, затем
`zone.js/testing`, затем `zone.js/plugins/vitest-patch` — вместе с проверенной матрицей совместимости
(Angular 20 / Vitest 3 / jsdom 26, только zoneless; Angular 21 и 22 / Vitest 4 / jsdom 28, с зоной или
без). Последуйте ей — и получите поведение плагина, а оно вот такое. Измерено на Vitest 4.1.9 с
zone.js 0.16.2, по одному файлу спеки на API:

| В спеке                                 | Без плагина            | С `zone.js/plugins/vitest-patch`                                                                   |
| --------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------- |
| `it.skip` / `it.todo` / `it.concurrent` | попадают в отчёт       | **теста нет, а прогон завершается кодом 0**                                                        |
| `it.only`                               | выполняется только он  | **этого теста нет; выполняется несфокусированный**                                                 |
| `it.each`                               | проходит               | **`TypeError: Cannot read properties of undefined (reading 'apply')`, ни одного теста не собрано** |
| `describe.skip`                         | пропускается           | **сюита выполняется**                                                                              |
| `describe.only`                         | выполняется только она | **выполняются все сюиты**                                                                          |
| `test.extend`                           | фикстуры работают      | **`TypeError: test.extend is not a function`**                                                     |
| `test: { globals: false }`              | —                      | ничего не патчит, ни о чём не предупреждает, каждый `fakeAsync` по-прежнему падает                 |

Причина в том, что он подменяет глобалы раннера обычными функциями и прицепляет к ним десяток
захардкоженных имён, так что `it.extend`, `it.fails` и `it.scoped` теряются совсем, а `it.skip`, `it.only`
и `it.todo` превращаются в фабрики, возвращающие функцию, вместо того чтобы регистрировать тест. Он
сохраняет `fn.length`, но не `fn.toString()`, а именно его Vitest читает, чтобы найти деструктурированные
фикстуры. Тот же файл под `vitest-auto-spy/zone` воспроизводит непропатченный прогон в точности.

Справедливости ради: простой `fakeAsync` в голом `it` внутри голого `describe` под официальным плагином
работает. Он решает задачу, которую ставил перед собой, — для спек, не использующих ни одного
модификатора теста.

## Что он делает {#what-it-does}

`fakeAsync` нужно одно: колбэк, который он оборачивает, должен выполняться внутри зоны, несущей
`ProxyZoneSpec`, потому что именно в этот spec он подставляет свой `FakeAsyncTestZoneSpec`. Поэтому патч
выполняет тело каждого теста и каждого хука внутри форкнутой прокси-зоны.

Сложность — сделать это, не потревожив раннер, и все три способа ошибиться здесь дают падения в _чужих
файлах_; каждый из них измерен выше на официальном плагине, а не выдуман:

| Деталь                                   | Что ломается без неё                                                                                                                                  |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| у обёртки **нет** параметров             | Vitest читает `fn.toString()`, чтобы найти фикстуры; `function (...args)` роняет каждый файл с `FixtureParseError: … must use object destructuring`   |
| `fn.length` и `fn.toString()` перенесены | раннер читает оба, чтобы решить, как вызвать колбэк, — обёртка с арностью 0 молча меняет это решение и прячет фикстуры                                |
| `it` **проксируется**, а не подменяется  | `each` — метод, читающий `this`; вызванный отдельно, он возвращает `undefined`, и следующая строка взрывается. `it.skip` / `test.each` идут в подарок |

## Одна зона на прогон или по одной на колбэк {#one-zone-for-the-run-or-one-per-callback}

```ts
import { installProxyZonePatch } from 'vitest-auto-spy/zone';

installProxyZonePatch({ scope: 'callback' });
```

`scope: 'shared'` — значение по умолчанию: тела всех тестов и хуков прогона проходят через **одну**
прокси-зону. Так делает собственный jasmine-патч Angular, и под это написана экосистема: компонент,
собранный в `beforeEach`, планирует таймеры из конструктора, и `tick()` внутри `fakeAsync`-теста обязан
их видеть. Форкните на каждый колбэк — и они окажутся в разных зонах, а тест будет ждать таймер, который
никто никогда не спустит.

`scope: 'callback'` — это и есть форк на каждый колбэк. В абстракции он правильный, а для
`test.concurrent` — обязательный: там два колбэка выполняются одновременно и иначе подменяли бы друг у
друга делегата одного и того же `ProxyZoneSpec`.

## Требования {#requirements}

**`test: { globals: true }`.** Патч работает подменой глобалов раннера; `it`, импортированный из
`'vitest'`, — это привязка модуля, до которой не дотянется ничто, никакой патч ни в каком пакете.

**zone.js загружен первым, вами.** Эта точка входа ничего из него не импортирует. Под
`@angular/build:unit-test` билдер уже грузит оба бандла из собственной точки входа; иначе импортируйте их
в начале сетап-файла. Если их нет, патч говорит, какой половины не хватает:

```text
[vitest-auto-spy] vitest-auto-spy/zone: globalThis.Zone is not there, so there is nothing to patch.
This entry deliberately does not import zone.js — a zoneless project must not pull it in — …
```

## Почему это отдельная точка входа {#why-it-is-a-separate-entry}

**zone.js — это `devDependency` данного пакета и больше ничего**: не зависимость, не опциональный peer.
`vitest-auto-spy` не объявляет рантайм-зависимостей вообще, так что его установка не может затянуть
zone.js ни в чьё дерево.

И ни одна другая точка входа библиотеки не добирается до этого модуля, даже транзитивно: `dist/zone.js`
самодостаточен, и ничто в `dist/` на него не ссылается. Zoneless-проект, импортирующий `vitest-auto-spy`,
не получает ни зонного кода, ни зонного импорта, ни единого байта этого файла. Это инвариант пакета, а не
случайность релиза — см. `AGENTS.md`.

`installProxyZonePatch()` экспортируется для сетап-файла, который предпочитает вызвать его явно; он
возвращает функцию отката.
