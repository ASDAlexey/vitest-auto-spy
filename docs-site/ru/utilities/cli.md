# CLI

Четыре команды, ни одной зависимости, ничего не нужно настраивать:

```bash
npx vitest-auto-spy doctor   # только чтение. Выходит с кодом 1, когда что-то нашёл
npx vitest-auto-spy perf     # куда уходит CPU-время сюиты. Всегда выходит с кодом 0
npx vitest-auto-spy init     # пишет указатель на инструкции для агентов
npx vitest-auto-spy codemod  # по умолчанию сухой прогон. Выходит с кодом 1, когда что-то оставил как было
```

Это один бинарник, потому что все четыре отвечают на один вопрос с четырёх сторон — _не делает ли
что-нибудь в этой тестовой сюите молча совсем не то, чем кажется?_ `doctor` задаёт его репозиторию,
`perf` — собственным часам сюиты, `init` — агенту, который вот-вот напишет следующую спеку, а
[`codemod`](/ru/utilities/codemod) — каждому фрагменту, который переезд с `jest-auto-spies` иначе
переименовал бы в противоположный смысл. Эта страница про первые три; у кодмода
[своя страница](/ru/utilities/codemod), потому что бо́льшая часть его работы — отказываться.

## `doctor` — дефекты, которые никогда не падают {#doctor-—-defects-that-never-fail}

У всех проверок здесь одно общее свойство: **результат никто не потребляет**. Сюита зелёная,
`tsc --noEmit` показывает ноль ошибок, и единственный читатель протухшей вещи — человек, который
случайно открыл этот файл. Именно поэтому такие дефекты живут годами, и по той же причине линтер
почти ни один из них не найдёт — улики размазаны по файлам.

```
         zero errors. Fix the glob or delete the entry.

```

Проверка, ради которой инструмент и появился: спека показывала `Cannot find name 'vi'` в редакторе,
пока `tsc --noEmit` рапортовал ноль ошибок. Кодмод миграции, правивший `include`, съел `/**`,
превратив `src/**/*.spec.ts` в `src*.spec.ts` — синтаксически валидный глоб, не совпадающий ни с
чем. Из 152 tsconfig'ов спек свои спеки покрывали только девять.

**Он никогда не пишет.** `doctor` читает репозиторий и печатает; никакого `--fix` нет. Код возврата
1, когда нашлось что-то выше заметки, иначе 0, — так что он вставляется в CI одной строкой.

Два вида паттернов сознательно исключены, потому что для них «ни с чем не совпадает» ничего не
доказывает: глоб только по декларациям (`src/**/*.d.ts` — рутинная заглушка под ambient-типы,
которых ещё нет) и паттерн с корнем в директории, куда сканер вообще не заходит (`dist`, `out-tsc`,
`coverage`).

### Две проверки, которые разрешают имя {#the-two-checks-that-resolve-a-name}

`helper-from-wrong-entry` и `no-unawaited-helper` обе отвечают на вопрос про имя, и ни одна не
гадает. Таблица точек входа, которую они читают, **генерируется из собственной карты `exports` этого
пакета** — barrel-модули компилируются, экспортированные символы берутся у компилятора, а набор функций,
возвращающих промис, — из сигнатур, а не из списка, набитого руками. Написанная руками копия
разъехалась бы при первом же переезде хелпера между точками входа — и разъехалась бы молча.

Поэтому же это проверки `doctor`, а не правила линтера: у пофайлового линтера такой таблицы нет.

Обе сознательно консервативны.

- Таблица описывает одну мажорную версию. `doctor` читает версию, реально установленную в
  репозитории, и молчит, когда мажоры расходятся, — хелпер переезжает между точками входа только в
  мажоре.
- `no-unawaited-helper` рапортует одну-единственную форму — вызов, который и начинает инструкцию, и
  заканчивает её. Всё, откуда промис ещё может утечь наружу, остаётся нетронутым: `await`, `return`,
  присваивание, аргумент, `.then`, короткое тело стрелки, явный `void`. Как и одноимённый метод, и
  любой вызов, чей callee этот файл у нас не импортировал. `expectEmission`, переименованный через
  `as`, всё равно разрешается; чужой `stable` — никогда.
- Ни одна не читает текст, который не является кодом. Строки, шаблонные литералы и комментарии
  вырезаются до всякого сопоставления, так что фикстура кодмода, генератор документации, цитата в
  заголовке `describe` или закомментированная строка не попадут в отчёт никогда. Комментарии
  вырезаются первыми, потому что апостроф в прозе иначе открыл бы строку. Именно этот случай и
  определил дизайн: собственные спеки этого пакета цитируют import-инструкции, и проверка, которая
  бы на них рапортовала, была бы красной на репозитории, который её и поставляет.

На собственных 758 исходниках этого репозитория обе не находят ровным счётом ничего.

**Всё ещё только чтение.** Обе находки называют механическую правку — поменять специфер, добавить
`await`, — и ни одна не применяется. Никакого `--fix` в `doctor` нет вообще, и это решение, а не
пробел: инструмент, который только что сообщил вам о четырёх вещах, которых больше никто не видел,
ещё не заслужил права писать в прочитанные им файлы.

## `perf` — куда на самом деле уходит время CPU {#perf-—-where-the-cpu-time-actually-goes}

Vitest печатает одну итоговую строку на прогон — `Duration 8.91s (transform 26.20s, setup 14.70s,
import 55.27s, tests 27.24s, environment 155.65s)`, — и это единственное место, где эти шесть чисел
вообще появляются. Она говорит, что подготовка среды — 56 % времени CPU; она не говорит, какие из
1 400 спек сюиты вообще не нуждались в DOM. `perf` читает те же числа по каждому файлу через
`TestModule.diagnostic()` — собственный публичный аксессор Vitest, через репортер, который
поставляет этот пакет, — и превращает доминирующую фазу в список файлов и правило, по которому они
туда попали. Никакого разбора вывода терминала здесь нет.

```bash
npx vitest-auto-spy perf              # прогнать всю сюиту один раз и отчитаться
npx vitest-auto-spy perf src/cli      # путь передаётся в Vitest как фильтр по файлам
npx vitest-auto-spy perf --json out/perf.json   # разобрать готовый отчёт вместо прогона Vitest
npx vitest-auto-spy perf --out out/perf.json    # сохранить JSON, который пишет этот прогон
```

Это собственная сюита этого репозитория. Она называет ноль кандидатов на жизнь без DOM и оставляет
109 файлов нерешёнными, потому что `src/test-setup.ts` строит Angular `TestBed` перед каждой
спекой, — правило ниже как раз объясняет, почему настоящий репозиторий получает честное «не могу
сказать» вместо догадки.

**Суммы по фазам — это время CPU, сложенное по воркерам**, а не время по часам: прогон выше занял
860 мс на часах и 17,30 с CPU, потому что работа разошлась по нескольким воркерам. Сумма фазы
больше времени по часам — не баг.

| Фаза          | Что измеряет Vitest (формулировки его собственного `ModuleDiagnostic`)                             |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `environment` | Время на импорт и инициализацию среды (`jsdom`, `happy-dom`, `node`) для файла                        |
| `prepare`     | Время, которое Vitest тратит на подготовку тестовой обвязки — раннера, моков — для файла              |
| `import`      | Время на импорт тестового модуля: всего, что он импортирует, плюс выполнение его suite-колбэков       |
| `setup`       | Время на импорт настроенных setup-файлов для этого файла                                             |
| `tests`       | Накопленная длительность самих тел тестов и хуков                                                    |
| `transform`   | Время трансформации за весь прогон (esbuild/Vite); по файлам не считается, поэтому находок по нему нет |

Фаза порождает находки, только когда она стоит чьего-то вечера: ниже 30 % от общего времени или
ниже 5 с суммарного CPU за весь прогон `perf` так и говорит и на этом останавливается, а не называет
файлы поверх шума.

**`perf-environment`** срабатывает, когда доминирует `environment`. Он ранжирует каждую спеку,
которая *обходится без DOM* — доказуемо, а не вероятно, — по потраченному ею времени среды и
предлагает для каждой `// @vitest-environment node` (или проект со средой `node`). Правило намеренно
одностороннее: спека становится кандидатом, только если она сама, настроенные setup-файлы и каждый
модуль репозитория, который кто-то из них импортирует, были прочитаны, ни в одном из них не
упоминается DOM-имя, а все импортируемые ими пакеты входят в короткий белый список без DOM
(`vitest`, `rxjs`, `date-fns`, `lodash`, `zod`, …). Всё, что правило не смогло разрешить, — импорт,
за которым не пройти, пакет вне списка — попадает в **нерешённые**, а не в безопасные по умолчанию:
ложное срабатывание — это чья-то сюита, падающая на `document is not defined`, и это дороже, чем
упущенная оптимизация. На этом репозитории правило не называет ничего и относит 109 файлов к
нерешённым — по причине выше.

**`perf-import`** срабатывает, когда доминирует `import`, и называет каждую спеку, которая
добирается до своего предмета через barrel — модуль `index`/`public-api` без собственных объявлений,
одни реэкспорты, — потому что спека, импортирующая такой модуль, грузит всё, что barrel реэкспортит,
ради одного экспорта из неё. В прогоне выше он не срабатывает: `import` — всего 5,1 % от суммы этого
репозитория.

**`perf-isolation`** срабатывает, когда `environment` + `setup` + `prepare` доминируют вместе, и
показывает на `test.isolate: false` — настройку, которая платит за эти три раз на воркер, а не раз
на файл. Он подан как сделка, а не как выигрыш, и ссылается на собственные замеры памяти этого
пакета ([`core/performance#memory-under-isolate-false`](/ru/core/performance#memory-under-isolate-false)),
а не повторяет числа здесь: без изоляции каждый дубль, созданный файлом, живёт до конца воркера, и
пиковая память растёт вместе с сюитой. `perf` не предлагает эту настройку, если `vite(st).config.*`
уже ставит `isolate: false`, — рапортовать о настройке, которую читатель уже сделал, это не находка.

**Код возврата.** `perf` при успешном анализе всегда выходит с `0` — медленная сюита не значит
падающая, поэтому сама по себе она никогда не роняет CI-джобу. Он выходит с `1` только когда читать
нечего: Vitest не установлен в `--cwd`, отсутствует собственный `dist/perf-reporter.js` пакета,
прогон Vitest не выдал отчёта или файл `--json` не парсится как отчёт. Если сюита прогналась, но
упала, `perf` всё равно рапортует измеренные тайминги — с предупреждением, что сам прогон не прошёл.

### Флаги {#flags}

| Флаг            | Что делает                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--cwd <dir>`   | Работать в другой директории вместо текущей (общий с остальными командами)                                              |
| `--json <path>` | Прочитать отчёт, записанный более ранним прогоном с `--out`, вместо повторного запуска Vitest                            |
| `--out <path>`  | Сохранить JSON-отчёт по этому пути. Без него отчёт пишется в `node_modules/.cache` и удаляется, как только его прочитали |

Позиционный путь (`npx vitest-auto-spy perf src/cli`) передаётся в Vitest как фильтр по файлам; без
него `perf` меряет всю сюиту.

## `init` — указатель, который агент действительно читает {#init-—-the-pointer-an-agent-actually-reads}

Ни в один контекст инструкций кодового агента нет пути без настройки. Каждый инструмент ищет правила
по фиксированному набору путей в корне репозитория или в dot-директориях, и **ни один не сканирует
зависимости** — ни скилл, ни `AGENTS.md`, лежащие внутри тарбола этого пакета, не находятся
автоматически. Что-то в репозитории должно один раз на них показать.

```bash
npx vitest-auto-spy init
```

**Ярус 1, пишется всегда** — три корневых файла покрывают всё поле:

| Файл                                      | Кто читает                                                                                                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md`                               | Codex, Cursor, Copilot, Cline, Windsurf, Zed, OpenCode, Qwen, Roo, Junie, Aider                                                                                |
| `CLAUDE.md`                               | Claude Code, а также GLM / Kimi, работающие внутри него                                                                                                       |
| `GEMINI.md`                               | Gemini CLI, который по умолчанию не читает `AGENTS.md`                                                                                                        |
| `.claude/skills/vitest-auto-spy/SKILL.md` | Claude Code — заглушка, чей frontmatter скопирован дословно из поставляемого скилла, а тело только показывает на `node_modules`, так что протухнуть оно не может |

**Ярус 2, только когда собственная директория инструмента уже существует**, и с ограничением по
глобу, чтобы задача не про тесты не платила за это контекстом: `.cursor/rules/`,
`.github/instructions/`, `.windsurf/rules/`, `.devin/rules/`, `.clinerules/`, `.roo/rules/`.

**Никогда не создаётся:** `.rules`, `.cursorrules`, `.windsurfrules` или `.clinerules` в виде
_файла_. Zed разрешает инструкции по принципу «побеждает первое совпадение» по упорядоченному
списку, который заканчивается `AGENTS.md`, так что создание любого из них молча затеняет инструкции
всего проекта. Если такой файл уже есть, `init` дописывает в него, а не оставляет его протухшим.

### Почему команда, а не сниппет {#why-a-command-rather-than-the-snippet}

[Сниппет для копипасты](/ru/agents) вынужден перечислять каждый раннер и каждый адаптер, и половина
его для любого конкретного репозитория ложна. `init` читает `package.json` потребителя и конфиг
тестов и пишет только истинную половину — какой subpath подходит этому раннеру, какой адаптер
подходит фреймворку, реальный путь к setup-файлу, которому нужен `import 'vitest-auto-spy/rxjs'`, — и
целиком опускает пункт про rxjs, когда rxjs не установлен.

### Идемпотентен по построению {#idempotent-by-construction}

Всё пишется между маркерами:

```md
<!-- vitest-auto-spy:begin v=3.7.0 sha=90452bea -->

…

<!-- vitest-auto-spy:end -->
```

Текст между ними перегенерируется целиком на каждом прогоне; текст снаружи не читается и никогда не
переформатируется. Запуск `init` после обновления — это либо no-op, либо диф в один хунк. `CLAUDE.md`,
который является симлинком на `AGENTS.md` или уже содержит строку импорта `@AGENTS.md`, остаётся
нетронутым — оба способа держат один файл инструкций, и запись через любой из них продублировала бы
блок.

Блок сознательно держат меньше 1,6 кБ. Codex ограничивает всю цепочку `AGENTS.md` от корня до cwd
значением `project_doc_max_bytes` (по умолчанию 32 768 байт) и молча обрезает всё сверх него, так что
`init` предупреждает, когда файл, в который он дописал, эту границу перешёл.

### Флаги {#flags-1}

| Флаг              | Команда      | Что делает                                                                    |
| ----------------- | ------------ | ------------------------------------------------------------------------------- |
| `--cwd <dir>`     | все четыре   | Работать в другой директории                                                   |
| `--check`         | `init`       | Ничего не писать; выйти с 1, если блока нет или он устарел. Форма для CI        |
| `--dry-run`       | `init`       | Напечатать, что изменилось бы, и ничего не писать                              |
| `--uninstall`     | `init`       | Убрать управляемые блоки и удалить файлы, созданные `init`                     |
| `-h`, `--help`    | все четыре   | Экран справки                                                                  |
| `-v`, `--version` | все четыре   | Установленная версия                                                           |

Собственные флаги `perf` — `--json`, `--out` — в [его разделе выше](#perf-—-where-the-cpu-time-actually-goes).
Собственные флаги кодмода — `--write`, `--verify`, `--only`, `--skip`, `--list` — на
[его странице](/ru/utilities/codemod#flags).

`init --check` в CI устроен так же, как `llms:check` в этом репозитории: он падает, когда блок на
диске — не тот блок, который написала бы установленная версия, то есть ровно тогда, когда обновление
изменило совет.

## В CI {#in-ci}

```yaml
- run: npx vitest-auto-spy doctor
- run: npx vitest-auto-spy init --check
- run: npx vitest-auto-spy codemod --verify # на сюите, которая уже переехала
- run: npx vitest-auto-spy perf --out perf.json # всегда выходит с 0 — не ворота, а артефакт на память
```

Ни одной из них не нужны сеть, конфиг-файл или токен. CLI поставляется вместе с пакетом, не имеет
собственных рантайм-зависимостей и является единственной его частью, которой позволено трогать
`node:fs`, — этот инвариант репозиторий проверяет на каждой сборке.
