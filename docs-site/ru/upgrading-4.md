# Переход на 4.0

## Зачем обновляться {#why-upgrade}

У этого мажора одна задача — снять с вашего проекта вес, который библиотека заставляла его тащить. Он
не добавляет ни одной возможности, не убирает ни одного хелпера и не меняет поведение в рантайме:
каждое число ниже — это то, за что ваш проект перестаёт платить.

| Что вы получаете                                                                                                                                                                                   | Измерено                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **rxjs уходит из вашей TypeScript-программы.** Публикуемые декларации упоминали `Observable` и `Subject`, поэтому rxjs подгружался каждому потребителю независимо от того, пользуется ли им проект | программа **303 → 114 файлов**, из них **189 → 0** приходятся на rxjs                    |
| **Поставляемый `.d.ts` перестаёт падать без опционального peer-пакета**                                                                                                                            | `TS2307` при `skipLibCheck: false` и без установленного rxjs: воспроизводилось → исчезло |
| **Каждый файл спеки, который не трогает DOM-глобалы, получает время назад**                                                                                                                        | **−0.159 мс на файл**; корневая точка входа **15.5 → 12.9 кБ** min+gzip                  |
| **Вторая копия rxjs перестаёт молча ломать распознавание observable**                                                                                                                              | `nextWith is not a function`, где ничто не указывало на дубликат → хелперы на месте      |
| **Правила линтера перестают решать за ваш проект, насколько ему не всё равно**                                                                                                                     | все девятнадцать — `error`, ручка регулировки описана по каждому правилу                 |

А цена — два импортных спецификатора плюс один импорт, если вы аннотируете `returnSubject()`. Вот и
всё, а остальная часть страницы — этот список с той самой строкой, которая чинит каждый пункт.

Если вы пользуетесь observable-хелперами, оставьте `import 'vitest-auto-spy/rxjs'` где-нибудь внутри
того, что попадает в `tsconfig`, — именно этот импорт держит `returnSubject()` типизированным как
родной `Subject<T>` из rxjs.

## Что изменилось {#what-changed}

**Три ломающих изменения, и ни одно из них не меняет того, что делает спай.** Ни один хелпер не
удалён и не переименован, ни один ключ конфигурации не поменял смысл, поведение в рантайме везде
прежнее. Изменились места, откуда импортируются две группы хелперов, тип `returnSubject()` и
громкость правил линтера. Большинство сюит обновляется так: сменить версию, прогнать тесты и починить
то, на что после этого пожалуются проверка типов и линтер.

|                                                                                                                  | Что делать                                                                                       |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| [1. rxjs ушёл из деклараций](#_1-rxjs-left-the-published-declarations)                                           | обычно ничего; один импорт, если вы аннотируете `returnSubject()`                                |
| [2. DOM-заглушки и диагностика прогона переехали](#_2-dom-stubs-and-run-diagnostics-moved-to-their-own-subpaths) | сменить спецификатор импорта у тринадцати хелперов — во всех точках входа, реэкспортирующих ядро |
| [3. Каждое правило линтера — ошибка](#_3-every-eslint-rule-is-an-error)                                          | ничего или один блок конфигурации                                                                |

## 1. rxjs ушёл из публикуемых деклараций {#_1-rxjs-left-the-published-declarations}

`vitest-auto-spy` всегда держал rxjs за опциональным подпутём `vitest-auto-spy/rxjs` — в рантайме. На
уровне типов этого не было: общий чанк деклараций открывался строкой
`import { Observable, Subject } from 'rxjs'`, а TypeScript разрешает импорт только типов ровно так
же, как импорт значений, — поэтому программа каждого потребителя подгружала rxjs независимо от того,
пользуется ли им проект, а потребитель без опционального peer-пакета получал `TS2307` внутри
поставляемого `.d.ts` при `skipLibCheck: false`.

Измерено на опубликованном пакете для потребителя, у которого всё использование библиотеки — это
`createSpyFromClass` на сервисе, возвращающем промисы:

|                                                              | 3.18 |     4.0 |
| ------------------------------------------------------------ | ---: | ------: |
| файлов в программе TypeScript                                |  303 | **114** |
| из них `.d.ts`-файлов rxjs                                   |  189 |   **0** |
| `TS2307` при `skipLibCheck: false` и без установленного rxjs |   да |     нет |

Полное объяснение, включая то, почему `import type` этого не чинит, — на
[странице про rxjs](/ru/runtimes/rxjs#rxjs-in-the-types).

### Касается ли это вас? {#does-it-affect-you}

Прогоните проверку типов. Пожаловаться она может на два случая, и распространён из них только первый.

#### `returnSubject()` больше не `Subject` из rxjs — если только слой не входит в вашу программу {#returnsubject-is-not-an-rxjs-subject-any-more-—-unless-the-layer-is-in-your-program}

`returnSubject()` и `nextWithPerCall()` теперь возвращают `SubjectOf<T>`, и это **и есть** родной
`Subject<T>` из rxjs — при условии, что `vitest-auto-spy/rxjs` входит в программу, в рамках которой
TypeScript проверяет ваши спеки. Если не входит, они возвращают структурный `SubjectLike<T>` —
`next`, `error`, `complete`, `asObservable`, всё, ради чего к хелперу и обращаются, — и вот такая
аннотация перестаёт компилироваться:

```ts
const subject: Subject<Product[]> = service.getProducts$.returnSubject();
//    ~~~~~~~ Type 'SubjectLike<Product[]>' is not assignable to type 'Subject<Product[]>'
```

Чинится одной строкой в файле, который включён в ваш `tsconfig`:

```ts
import 'vitest-auto-spy/rxjs';
```

Это тот же импорт, который observable-хелперам и так нужен в рантайме; если ваша сюита вообще
вызывает `nextWith`, он где-то в репозитории уже есть. Ошибка сообщает лишь о том, что он лежит там,
куда **компилятор** не заглядывает, — как правило, в файле из `setupFiles` Vitest, который не включён
ни в один `tsconfig`. Добавьте файл в `include` или перенесите импорт на сторону спек.

Сюиты, которые результат не аннотируют (`const subject = spy.load.returnSubject()`), это не
затрагивает никак.

#### Распознавание структурное, так что продублированный rxjs теперь подходит {#detection-is-structural-so-a-duplicated-rxjs-now-matches}

Член считается observable, когда его тип имеет `subscribe` и `forEach(next)`, возвращающий промис.
`Observable` из rxjs, любой `Subject` и ангуляровский `EventEmitter` этому удовлетворяют; `Promise`,
массивы, `Signal` и ангуляровский `OutputEmitterRef` — нет, так что ничто из бывшего обычным спаем
не станет observable-спаем по случайности.

Один случай меняется в полезную сторону: `Observable`, приехавший из **второй копии rxjs** в дереве
зависимостей. `Subject` номинален — у него есть приватное поле, — поэтому продублированный rxjs
раньше вовсе пролетал мимо observable-обвязки, и симптомом было `nextWith is not a function`, где
ничто не указывало на дубликат. Теперь это работает.

Если у вас есть самописный тип потока, у которого случайно оказались оба члена, он теперь будет
считаться observable. Это и есть задуманное расширение; а если для вашего типа оно неверно — назовите
член в `methodsToSpyOn` / `onlyMethodsToSpyOn` вместо того, чтобы полагаться на вывод.

## 2. DOM-заглушки и диагностика прогона переехали на свои подпути {#_2-dom-stubs-and-run-diagnostics-moved-to-their-own-subpaths}

Тринадцать хелперов покинули **все точки входа, реэкспортирующие ядро**, — `vitest-auto-spy`,
`/bun`, `/bun-angular`, `/node`, `/react`, `/vue` и `/svelte`, так что импорт из `/react` вместо
корня от этого не спасает. В самих хелперах не изменилось ничего — те же функции, те же сигнатуры,
тот же журнал отката, — только спецификатор:

| Было                                                                                                                                                                                      | Стало                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `stubIntersectionObserver`, `stubResizeObserver`, `stubMutationObserver`, `stubObserver`, `intersectionEntry`, `resizeEntry`, `mutationRecord`, `stubMediaElement`, `stubAbortController` | `vitest-auto-spy/dom-stubs`   |
| `compareTestRuns`, `summarizeTestRun`, `formatTestRunComparison`, `diffByField`                                                                                                           | `vitest-auto-spy/diagnostics` |

Их типы переехали вместе с ними: `ObserverStub`, `ObserverStubOptions`, `ObserverGlobal`,
`ObserverInstance`, `IntersectionObserverStubOptions`, `MutationRecordInit`, `ResizeEntryRect`,
`MediaElementState`, `MediaElementStub` и `MediaElementStubOptions` — из `/dom-stubs`;
`TestRunComparison`, `TestRunReport` и `TestRunSummary` — из `/diagnostics`.

```ts
// было
import { createSpyFromClass, stubIntersectionObserver } from 'vitest-auto-spy';

// стало
import { createSpyFromClass } from 'vitest-auto-spy';
import { stubIntersectionObserver } from 'vitest-auto-spy/dom-stubs';
```

Компилятор найдёт вам каждое из этих мест, а `npx vitest-auto-spy codemod` перепишет импорты — он
читает карту `exports` установленного пакета, а не табличку, поэтому переносит каждое имя в ту точку
входа, где оно действительно есть.

**Почему.** Реэкспорт в ESM жадный, а тестовые файлы никакой раннер не тряхнёт tree-shaking'ом, так
что единственный способ перестать исполнять модуль — перестать его экспортировать. Каждая спека в
каждом проекте — включая Node-сервисы, где DOM нет вовсе, — исполняла 27 кБ кода про observer'ы,
медиаэлементы и `AbortController` ради `createSpyFromClass`. Измерено на собранном пакете, по
процессу на замер, медианы 40 парных прогонов:

|                                                    |                           изменение |
| -------------------------------------------------- | ----------------------------------: |
| файл спеки, который их **не** импортирует          |                       **−0.159 мс** |
| файл спеки, который **импортирует** `/dom-stubs`   |                           +0.155 мс |
| файл спеки, который **импортирует** `/diagnostics` |                           +0.069 мс |
| `dist`                                             | **−20.3 кБ** JS, −3.8 кБ деклараций |

Обе новые точки входа собираются отдельно, а не чанками, — именно поэтому во второй строке один
лишний модуль, а не четыре: с чанками тот же замер показывал **+0.62 мс**. То есть размен идёт на
файлы, а не на проект: пока DOM-заглушки импортирует меньше половины ваших файлов спек, сюита в
выигрыше.

## 3. Каждое правило ESLint — ошибка {#_3-every-eslint-rule-is-an-error}

`configs.recommended` раньше раздавал своим девятнадцати правилам оценки `error` / `warn` / `off`.
Теперь все они `error` — с одним исключением, появившимся позже: `prefer-render-shallow` приходит как
`warn`, потому что сообщает про цену, а не про дефект. Почему — на [странице плагина](/ru/utilities/eslint-plugin#rules).

`warn` — это находка, из-за которой сборка не останавливается, так что в репозитории, где вывод
линтера никто не читает, это `off` плюс лишний шум; и неправильным было именно то, что выбор делался
за вас. Какие находки блокируют мерж — решение проекта и одна строка конфигурации в любую сторону,
поэтому по умолчанию взят строгий край, а [ручка регулировки описана в документации](/ru/utilities/eslint-plugin#tuning-it-for-your-project).

Если первый прогон красный, до всего остального стоит посмотреть на три правила — каждое из них может
пожаловаться на корректный код:

```js
export default [
  {
    files: ['**/*.spec.ts'],
    ...autoSpy.configs.recommended,
    rules: {
      ...autoSpy.configs.recommended.rules, // разворачивайте спредом, иначе голый ключ `rules` заменит всю карту
      // судит о слое, установленном в setup-файле, который не импортирует ни одна спека, — назовите этот файл
      'vitest-auto-spy/jasmine-namespace-without-entry': ['error', { setupModules: ['./test-setup'] }],
      // жалуется на рабочий переходный код — выключено, пока миграция с jasmine-auto-spies не закончена
      'vitest-auto-spy/prefer-native-spy-api': 'off',
      // опций нет; правило само молчит везде, где не может прочитать провайдеры файла целиком, так что
      // выключайте его только для тех файлов, где регистрацию делает вызываемый вами хелпер
      // 'vitest-auto-spy/no-unregistered-inject-spy': 'off',
    },
  },
];
```

Чтобы выкатить это на большую существующую сюиту и не получить красный CI в первый же день, возьмите
сначала всё как предупреждения и чините партиями — рецепт в разделе
[Настройка под ваш проект](/ru/utilities/eslint-plugin#tuning-it-for-your-project).

## Что _не_ изменилось {#what-did-not-change}

- Ни один хелпер не удалён, не переименован и не помечен устаревшим — две их группы сменили
  спецификатор, и это всё.
- Ни одно правило линтера не добавлено, не удалено и не поменяло того, на что жалуется; изменилась
  только громкость.

## Если вы идёте издалека {#coming-from-further-back}

[Переход на 3.0](/ru/upgrading-3) — это одна строка в `package.json`: диапазон peer-зависимости
`vitest` догоняет то, чего типы уже требовали. [Переход на 2.0](/ru/upgrading-2) важен, если вы всё
ещё на 1.x: `methodsToSpyOn` перестал молча удалять спаев, что довело один смигрированный компонент
со 147 упавших тестов до 4, а ленивые спаи методов ужали широкую сюиту с 257 мс / 425 МБ до 27 мс /
35 МБ.

- `nextWith`, `nextWithValues`, `nextOneTimeWith`, `throwWith`, `complete`, `observablePropsToSpyOn`
  и цепочки `calledWith` ведут себя точно так же.
- `rxjs` остаётся опциональной peer-зависимостью, которую импортируют `vitest-auto-spy/rxjs` и
  `vitest-auto-spy/observer-spy` и больше никто, — теперь и в декларациях, а не только в рантайме;
  именно на этом `scripts/check-dist.mjs` роняет сборку.
- Точки входа для Angular, NestJS, React, Vue, Svelte, Bun и `node:test` не изменились.
