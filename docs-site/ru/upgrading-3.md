# Переход на 3.0

## Зачем обновляться {#why-upgrade}

Самый маленький мажор, который выпускал этот пакет, и чинит он ровно одно — обещание, которое не мог
сдержать.

| Что вы получаете                                                                                                                                                                                                                                                                                                                                                         | Измерено                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| **Поддерживаемый диапазон перестаёт обещать версию, которую типы обслужить не могут.** `spy.method.mock.settledResults` — документированная часть API, и берётся она из собственного типа `Mock` в Vitest, а `settledResults` появился в `@vitest/spy` только в 2.0. На Vitest 1 эта часть API вообще не проходила проверку типов, хотя `package.json` заявлял `>=1.0.0` | размер `dist/`, скорость и память **не тронуты** — удалять нечего, версионных ветвлений тут нет |

## Что изменилось {#what-changed}

**Диапазон peer-зависимости `vitest` теперь `>=2.1.0`** (было `>=1.0.0`).

2.1, а не 2.0, потому что линейка 2.x фактически _и есть_ 2.1: на 2.0.x приходится ~0.3 % установок
Vitest против ~10 % у 2.1.x.

**Что делать.** Обновить Vitest — или остаться на `vitest-auto-spy@2.0.x`. В ваших спеках не меняется
ничего ни в том, ни в другом случае: это поддерживаемый диапазон догоняет то, чего типы уже требовали.

## И дальше {#then-keep-going}

[Переход на 4.0](/ru/upgrading-4) — тот, в котором есть числа: rxjs уходит из вашей
TypeScript-программы, и на каждом файле спеки возвращается 0.159 мс. Если вы идёте с 1.x, начните с
[Перехода на 2.0](/ru/upgrading-2) — это тот релиз, где `methodsToSpyOn` перестал молча удалять
спаев.
