# Переход на 3.0

В 3.0 минимальная версия Vitest поднята до 2.1. Спеки менять не нужно.

```bash
npm install -D vitest@latest vitest-auto-spy@3
```

**Что проверить**

1. Если у вас Vitest 1.x или 2.0.x, обновите Vitest до 2.1 или новее.
2. Если обновить Vitest пока нельзя, оставайтесь на `vitest-auto-spy@2.0.x`.

## Зачем обновляться {#why-upgrade}

| Что вы получаете                                                                                                                                                                                                                    | Измерено                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Поддерживаемый диапазон совпадает с тем, что нужно типам.** `spy.method.mock.settledResults` берётся из типа `Mock` самого Vitest, а там это поле появилось в 2.0. На Vitest 1 типы не сходились, хотя диапазон обещал `>=1.0.0`. | Размер `dist/`, скорость и память **не изменились**. Код не удалялся. |

## Что изменилось {#what-changed}

**Peer-диапазон `vitest` теперь `>=2.1.0`** (было `>=1.0.0`).

Почему 2.1, а не 2.0: версией 2.0.x почти никто не пользуется. На неё приходилось около 0,3 %
установок Vitest, а на 2.1.x — около 10 %.

**Что делать:** обновите Vitest или оставайтесь на `vitest-auto-spy@2.0.x`. Спеки в обоих случаях
не меняются.

## И дальше {#then-keep-going}

[Переход на 4.0](/ru/upgrading-4) убирает rxjs из вашей TypeScript-программы и экономит 0,159 мс на
каждом файле спеки. Переходите с 1.x? Начните с [Перехода на 2.0](/ru/upgrading-2) — там
`methodsToSpyOn` перестал убирать спаи.
